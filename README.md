# project-worklog · 项目工作台账

一个面向 Codex 的中文 Markdown 技能，用于交接长期项目。它把长期规则、最近核实的状态和逐项工作证据分开，让新对话能快速找到上次做到哪、下一步做什么，以及还有哪些地方需要核实。

适合本地环境维护、部署、实验和研究。台账以普通 Markdown 文件保存，可以只在本地使用，也可以配合 Git 保存版本。

## 默认管理布局

| 文件 | 内容 |
| --- | --- |
| `AGENTS.md` | 长期规则、授权边界和项目资料入口 |
| `STATUS.md` | 导航、未关闭工作、恢复条件与占用 |
| `logs/INDEX.md` | 历史工作索引及日志链接 |
| `logs/<工作ID>.md` | 续接摘要、逐轮记录、证据和恢复步骤 |
| `docs/maintenance.md` | 按主题定位当前方案、验收和恢复说明 |
| `docs/decisions.md` | 跨任务决定的理由、状态、替代关系及落实确认 |

一条事实指定一个主要维护位置，其他页面使用链接和必要摘要。配置、运行观察和功能验收各自保留时间与证据。已知工作先只读日志顶部最小续接资料，未知目标从状态页定位，主题咨询直达维护段落；遇到缺口、冲突或相关变化时再补读。综合总览用于初次了解或整体交接。

## 按需扩展的管理资料

各项目按需添加专题维护页，并从维护入口链接。已有台账可沿用功能等价的文件名，在项目规则里说明对应路径。新建或获授权迁移默认采用上表分工；用户可以明确选择合并职责的简化布局。现有台账继续按项目规则维护，结构迁移单独授权。

## 交付与验收

实施前明确完成条件，日志顶部分别写交付进度、实际功能验收及资源占用。讨论和只读核对可简记，复杂任务才增加计划或里程碑。证据注明对应构建/配置，以及在 Git、本机或私有位置的保存边界。

## 安装到 Codex

1. 从 GitHub 仓库的 **Code** 菜单下载 ZIP，或克隆仓库。
2. 将文件复制到下列任一位置，目录命名为 `project-worklog`。确保 `SKILL.md` 直接位于该目录内，并保留 `agents/`、`assets/` 和 `references/`。
   - 个人使用：`~/.agents/skills/project-worklog/`。Windows 对应用户目录下的 `.agents\skills\project-worklog\`。
   - 项目共享：`<项目根目录>/.agents/skills/project-worklog/`。
3. 在 Codex 的技能选择器中选择 `project-worklog`，或在对话中输入 `$project-worklog`。若技能未出现，确认目录位置和层级，再重启 Codex。 [Codex 技能说明](https://learn.chatgpt.com/docs/build-skills)

多项目可使用同一完整技能目录。换机器后核对该机器实际加载的副本；初始化或迁移前检查并读取本次需要的模板，发现缺失时补齐后再处理对应入口。

## 开始使用

**首次采用**

> 使用 $project-worklog 按默认布局为当前项目建立台账。先检查已有资料和本次所需模板，保留项目规则。本次只整理文档。

**交给新对话续接**

> 继续工作ID对应的任务。先读原日志顶部最小续接资料，缺信息再定向读证据；未知工作ID时从STATUS定位。按已有授权继续，保留未验边界。

**迁移已有台账**

> 使用 $project-worklog 按默认职责整理现有台账，沿用等价文件名。保留工作 ID、历史日志路径和证据，并核对暂停项能否续接。

技能只在明确选用时启用。采用台账、迁移现有文件、建立 Git 仓库和操作运行环境各按用户授权执行。

## Agent续接协议

日志顶部持久保存目标与授权、完成条件、当前停点、下一步及相关结论的来源和适用范围。摘要足够就执行获授权动作，缺口定向补读；冲突、相关变化或未知结果再扩大检查。持久变更前保存意图与同步欠项，中断后先查实际结果及后续编辑再重试。

必读项写可读路径与精确章节；迁移副本要提供出处映射，未生成输出不作为必读输入。项目或测试接口明确状态语义，完成状态与合并/恢复动作分开。历史迁移可增补有标记的续接区并保全原文，复测保留旧结果，不倒改预期制造通过。

## 工作方式

- **轻量记录**。讨论和低风险只读核对可合并记录来源、结论和限制。文件变更与高风险操作保留实际参数、验收、备份和恢复方法。
- **按任务续接**。同一目标跨对话沿用工作 ID。可以独立暂停或验收的工作另立关联项，暂停时写明恢复条件和当前占用。
- **可选 Git**。先确定纳管范围，再保存基线和审阅差异。台账继续记录变更原因和实际验收。大附件与私有材料按项目边界存放。 [Git 工作指南](references/git-workflow.md)
