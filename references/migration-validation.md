# 迁移与离线验证

先保存当前实际文件和未提交修改，列旧到新映射与恢复方式；保留工作ID、日志路径和原证据。检查技能与项目读取/更新规则是否冲突，按已授权范围同步，未迁移项目继续原规则。

以两个代表主题试迁。将常用结论提炼到维护入口，重要决定补状态/替代/落实确认；任务摘要补必读范围、相关版本和未决操作。索引核对全部工作，补录遗漏时保留来源时间。

验证使用解释、文档续接、模拟恢复等固定案例，预先冻结任务授权、预期判断和停止条件。加入版本冲突和中断后发生后续编辑的样例。执行者只拿任务及资料，预期答案由评审保留。提供可用输入清单、出处到副本的路径映射、精确标题和初始输出存在性；先定义结果状态与动作的区别。测试契约有歧义时保留旧结果，另存修订契约和复测，不倒改旧预期来制造通过。读取器分别记录成功、失败及范围。只在隔离副本操作，不访问真实服务或私有数据。

记录实际结果、读取批次/范围、正文量、重复读取、更新位置和同步遗漏。先判断授权/正确性/恢复安全，再比较开销。区分磁盘字节、实际返回正文、token遥测和端到端时间，不用字符数换算模型token，不宣称单次成功是稳定基准。

迁移收尾核对原资料、相关规则、链接/ID、决策关系、证据与配置对应及Git覆盖。全量哈希只用于必要完整性验证。局部变化只检查受影响范围。

技能有独立仓库时，先审阅源码，再同步本机并验证一致。记录安装、提交和远端发布状态，按授权执行。扩大项目迁移前先审阅代表案例结果。

全面迁移时可在原日志插入带标记的最小续接区，原正文逐字保留并保存改前副本/指纹；验证去除新增区后能还原原字节。旧摘要标为历史，避免与现行入口争夺权威。没有足够证据时写未知，不批量推断新的部署或验收。
