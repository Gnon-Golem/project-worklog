# 续接、读取与更新协议

## 最小续接资料

日志顶部与相邻固定元数据共同形成一次读取单元。四组必需资料为目标/授权/完成条件、状态/最后确认停点、下一步/等待或停止条件、已定结论与来源/适用范围。负责人和完整环境清单按需引用。

影响下一步时补未定事项与必读文件/章节，给出准确可读路径、精确章节名及读取用途，区分出处链接和本环境可用副本。迁移或隔离副本改变路径时，提供“原出处→可读副本”的直接映射及精确标题；输出文件是否存在也列清，未生成的输出不能作为必读输入。定位失败先查映射/目录清单，缺失材料记缺口，避免猜路径或近似标题连续重试。运行操作补当次现场与恢复前置条件。存在持久变更时，必须列变更ID、目标范围、需同步入口、已核对/待同步项、最后确认步骤/时间及证据；纯咨询可省略。

未知事实写未知，已取消验收记取消边界；关闭工作不自动生成未获授权的测试任务。基线按相关字段/配置段选择，整文件指纹变化不能直接否定所有旧结论。

## 渐进读取

1. 确认当前目标、有效规则与授权。已知任务用范围读取先取日志顶部，未知任务查状态，主题咨询定向读取维护页。整体交接时按需读总览；历史查找与决定追溯各走对应入口。
2. 判断下一步、所需事实、版本/范围是否足够；充分即执行已授权动作。
3. 有缺口只读指定章节、相关配置或最近证据，不机械遍历链接。
4. 有冲突、相关变化、未知操作结果或恢复依据缺失，先查直接来源和最近轮次，仍不明才展开更早历史或询问。
5. 相关变化使对应结论待复核，无关变化不扩大读取；摘要损坏时从入口和原记录重建并注明缺口。

不能按日期更晚直接覆盖不同范围决定。新指令优先，摘要不能扩大授权。现场变化另核对，历史PID/空闲/health不代替操作前检查。

## 强度选择

| 类型 | 默认动作 | 升级触发 |
| --- | --- | --- |
| 简单咨询 | 读相关结论与边界，合并简记 | 冲突或要求确认现场 |
| 长任务续接 | 读最小资料，写前检查目标与协调信息 | 中断、相关版本变化或证据不匹配 |
| 高风险操作 | 再核对实际对象、忙闲、影响与恢复条件 | 关键前提未知则调查或停止 |

## 状态语义

同一项目或机器接口明确状态含义，区分任务交付状态、验收范围和实际动作。合并/写入/恢复是动作，不单独充当完成状态；需要时另列动作字段。关闭任务可保留明确未验边界，不因此同时标“进行中”。已有项目采用其明确定义的状态词，不强制各项目共用英文枚举。

## 事件更新

一个项目事实只设一个主要维护位置。当前工作停点写任务顶部，采用方案写维护页，选择理由与落实依据写决策，活动状态、占用和入口写状态，历史定位写索引。其它页面使用链接和必要摘要。综合总览按交接需要整理，版本或结论变化时先更新其主要维护位置。

| 事件 | 需要更新 |
| --- | --- |
| 同主题讨论无新结论 | 可合并简记，其他资料保持 |
| 新结果改变判断或下一步 | 增量历史与任务摘要；任务状态变化再改状态页 |
| 提案接受/撤销/替代 | 决策，必要时维护说明；标明尚未落实部分 |
| 实施与验收 | 实际结果/证据、相关维护说明、落实确认与摘要 |
| 中断/交接 | 最后确认停点、未知结果、待同步项、恢复条件及占用 |
| 任务关闭 | 实际交付、验收边界、恢复入口和索引；无阻塞同步欠项 |

## 变更与中断恢复

持久变更前保存意图、范围、完成条件、恢复依据及待同步入口。操作后及时保存实际结果，完成长期资料及决策确认，再核销欠项；确有项目事实/任务状态变化才更新共享状态。

多文件没有跨文件原子保证。中断后先查操作是否实际发生、当前相关值和随后修改；在原授权内决定继续、合并、重做或停止。原意图不等于可安全重放，不能自动扩大为整套重测。

文件、部署与功能状态分开确认。部分实施明示范围，决定被接受时不提前标为运行已生效。Git提交只保存文件边界。

## 决策和长期成果

跨任务的重要选择集中记录，局部取舍留原日志。决策保存状态/来源/范围、理由、重要备选、后果、落实确认和重评条件。旧决定保留，新旧条目双向链接；不同范围可并存。用户要求、证实结论及工程假说分别表达。

反复使用的成果提炼进已有维护/使用说明，引用原变更和证据。组件内部资料归组件维护，主项目保存接口和集成关系；具体参数和服务约束留项目。
